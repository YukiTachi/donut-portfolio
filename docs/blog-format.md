# ブログ記事フォーマット規約

`src/content/blog/` に配置するブログ記事ファイルのファイル名・フロントマターの統一ルールをまとめたドキュメントです。

スキーマ定義: [`src/content/config.ts`](../src/content/config.ts)

---

## 1. ファイル名

### 命名規則

```
YYYY-MM-DD-slug.md
```

| 要素 | 説明 | 例 |
|------|------|-----|
| `YYYY-MM-DD` | 公開日（`pubDate` の日付と揃える） | `2026-02-22` |
| `slug` | 記事タイトルを元にしたスラッグ | `nutrisearch-本番リリースまでの道のり...` |
| 拡張子 | 必ず `.md` | `.md` |

### ルール

- **すべて小文字**（英字は lowercase）
- **スペースはハイフン `-`** に置換する
- 日本語をそのまま含めてよい（Decap CMS が自動生成）
- 記号（`×`, `——`, `、` など）はタイトルから引き継がれる場合がある

### 例（実ファイル）

```
2026-02-08-webサイトのセキュリティヘッダーを強化し、世界上位14-の評価を獲得しました.md
2026-02-13-ai時代のプログラミングスクール——変わるべきビジネスモデルと新しい学びの形.md
2026-02-22-nutrisearch-本番リリースまでの道のり――next-js-16-×-nextauth-js-v5-×-stripe-×-wintercms-で作る栄養検索サービス.md
```

> **注意**: Astro は記事の並び順・表示にファイル名ではなく `pubDate` を使用します。
> ファイル名の日付は管理上の目安なので、`pubDate` と揃えておくと混乱がありません。

## 2. フロントマター

記事の先頭に YAML 形式で記述します。**項目の順序も以下で統一**してください。

```yaml
---
title: 記事タイトル
description: 記事の説明文（SEO・一覧表示で使用。100〜300文字程度）
pubDate: 2026-02-22T08:44:00.000+09:00
author: Yuki Tachi
tags:
  - タグ1
  - タグ2
image: /blog-images/image.png
draft: false
---
```

### 項目一覧

| 項目 | 型 | 必須 | デフォルト | 説明 |
|------|-----|:---:|------|------|
| `title` | string | ✅ | — | 記事タイトル |
| `description` | string | ✅ | — | 記事の説明文。一覧・SEO に使用 |
| `pubDate` | date | ✅ | — | 公開日時。ISO 8601 形式。未来日時にすると予約公開（→ 5章） |
| `author` | string | ー | `Yuki Tachi` | 著者名 |
| `tags` | string[] | ー | — | タグの配列 |
| `image` | string | ー | — | アイキャッチ画像パス（`/blog-images/` 配下） |
| `draft` | boolean | ー | `false` | `true` で下書き（公開されない） |

### 各項目の記述ルール

- **`pubDate`**: JST の場合は `2026-02-22T08:44:00.000+09:00`、UTC の場合は `2026-02-22T00:00:00.000Z`。
  どちらも `z.coerce.date()` で正しくパースされる。
  **オフセット（`+09:00` / `Z`）は必ず付ける**。オフセットなしは UTC として解釈され、JST と9時間ずれる（予約公開の時刻もずれる）。
- **`image`**: 画像は `public/blog-images/` に置き、パスは `/blog-images/ファイル名` で参照する。
- **`tags`**: YAML のリスト形式（`- タグ名`）で記述。
- **`draft`**: 執筆中は `true`、公開時に `false`。予約公開する場合も、予約設定の時点で `false` にする。

## 3. 本文（Markdown）

```markdown
## 見出し（h2 から開始）

本文テキスト。

### 小見出し（h3）

- リスト
- リスト

\`\`\`ts
// コードブロックは言語を指定する
const x = 1;
\`\`\`

![代替テキスト](/blog-images/image.png)
```

### ルール

- 見出しは **`##`（h2）から開始**（`#` はタイトルとして使用済み）
- コードブロックは**言語を明示**する
- 画像は `/blog-images/` に配置してパス参照する
- 画像には `alt` テキストを付ける（アクセシビリティ）

## 4. 新規記事の追加方法

### 方法1: Decap CMS（推奨）

1. https://donut-software.com/admin/ にアクセスしてログイン
2. **New Blog** → 記事作成 → **Publish**
3. ファイル名・フロントマターは自動生成される

### 方法2: 直接ファイル作成

1. `src/content/blog/YYYY-MM-DD-slug.md` を作成
2. 上記フォーマットでフロントマター + 本文を記述
3. `git add` → `git commit` → `git push origin main`（自動デプロイ）

## 5. 予約公開

`pubDate` を未来日時にして `draft: false` で保存すると、その日時を過ぎた後の最初の定期ビルドで公開される。

### 手順（Decap CMS）

1. **PUBLISH DATE** を公開したい日時（JST）にする
2. **DRAFT** を OFF にして保存（Publish）
3. 予約日時を過ぎた後の定期ビルドで、記事ページ・一覧・sitemap に反映される

### 仕組み

- 公開判定は [`src/lib/posts.ts`](../src/lib/posts.ts) の `isPublished()` に集約している。
  個別ページ・ブログ一覧・404 の最近記事はすべてこの関数を通す（新たに `getCollection('blog')` を呼ぶ箇所を追加する場合も必ず使う）
- `draft: true` は常に除外。未来日付は**本番ビルドのみ**除外し、開発サーバ（`npm run dev`）では予約記事をプレビューできる
- 定期ビルドは `.github/workflows/deploy.yml` の schedule で**毎日 07:00 JST**（UTC 22:00）に実行される。
  push 時と同じくビルド → デプロイ → 内部リンク検査まで通る

### 注意点

- **公開タイミングは 07:00 JST 前後に丸められる**。GitHub の schedule は数分〜十数分遅れることがある。
  急ぐ場合は Actions 画面から `Deploy to FreeBSD` を手動実行（workflow_dispatch）する
- **予約中の記事へ他記事からリンクしない**。公開日まで 404 になり、デプロイ後の内部リンク検査が fail する。
  リンクする場合は、リンク元の公開を予約記事と同時かそれより後にする
- 未来日付のまま push しても記事は公開されない（ビルドから除外される）。日付を誤って未来にしていないか注意
- GitHub は一定期間コミットのないリポジトリの schedule を自動停止することがある。停止時は Actions 画面に表示されるので再有効化する
